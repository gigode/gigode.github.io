美团发布 LongCat-2.5 多模态智能体模型

Pandaily11月02日 22:35模型发布/更新
总参数约一点六万亿，面向长程工程任务。
▾

深度解读

美团 LongCat 团队发布 LongCat-2.5，将原生视觉理解与长程智能体编程作为重点。报道介绍，模型采用混合专家架构，总参数约一点六万亿，每个词元激活约四百八十亿参数；团队在长序列训练中加入更多长轨迹，并使用大规模长程强化学习，目标是让模型处理复杂代码库与完整项目。正式版本之前，预览版已于九月二十五日在 LongCat API 平台上线。总参数和每次实际激活量含义不同，不能把一点六万亿直接当成单次推理的计算量。

长程编程的难点在于跨多次文件读取、修改和测试保持目标一致，视觉能力则使模型能够参考界面截图，而不是只处理源代码。报道还提到针对国产算力优化四位权重和激活推理；量化可能降低部署资源需求，但代码任务的质量、上下文长度和不同硬件上的延迟仍需分别测量。模型团队报告的工程能力应与具体任务集、工具权限和执行预算一起理解，不能据参数规模推断其在所有真实项目中均优于其他模型。

Hydrogen-1.0 开放科学研究模型权重

Deep Principle／Hugging Face11月03日 02:41模型发布/更新
基于 GLM-5.3 后训练，模型卡标注约七千五百亿参数。
▾

深度解读

Deep Principle 发布科学研究助手 Hydrogen-1.0，模型卡称其以 GLM-5.3 为基础，利用科学数据、实验记录和研究发现轨迹进行后训练。公开模型卡标注参数规模为七千五百三十亿，支持一百万词元上下文，权重以 MIT 许可提供。研究机构因而可以检查和部署权重，也可以围绕自己的科研任务进行再训练；但可下载权重不等于全部原始实验数据和训练流程均已公开。

模型面向的问题包括科学推理和研究辅助，而不是直接替代实验室验证。团队公布的 FrontierScience-Research 成绩为百分之三十八点三，并与其他模型作比较；这是发布方在特定基准与测试条件下的结果，不能视作新药、材料或实验结论已经得到验证。长上下文有利于放入论文与实验记录，七千多亿参数也意味着显存、计算和部署费用可能很高，实际使用时仍要考虑量化后质量、证据引用是否准确，以及科学结论能否独立复现。研究者如果要自己部署，还需要区分许可条款、硬件容量和具体服务提供商的访问要求。

来源：Deep Principle／Hugging Face

Unsloth 提供 DeepSeek Flash 量化权重

Unsloth／Hugging Face11月02日 22:43模型发布/更新
发布多种 GGUF 量化格式，方便本地或自托管推理。
▾

深度解读

Unsloth 提供 DeepSeek-V4.1-Flash-1017 的 GGUF 权重文件及多种量化配置，供使用兼容推理引擎的开发者下载。候选池中的 Unsloth 说明还列出其在长上下文任务上的内部比较；这些数字来自模型提供者自己的测试，不能直接代表用户在不同机器和工具链上的表现。此处的更新是第三方量化及部署选择，不应误称 DeepSeek 在当天重新发布了基础模型。

量化将部分权重用较低精度保存，通常能减少存储和内存压力，但不同层的精度安排会影响推理结果。模型文件页面提供多个配置，用户需要同时核对权重大小、上下文缓存占用和所用推理程序的兼容性，不能只根据某个量化标签估算整机资源。对代码或代理任务，合理比较应固定测试集、上下文长度和生成预算，再分别记录错误率与首字延迟；低位宽能否接受取决于这些真实任务的结果。例如代码基准中的一次通过率，不能代替多轮工具调用中的最终修复成功率。

来源：Unsloth／Hugging Face

Claude API 公测消息线程，减少重复上传

Anthropic 开发文档11月02日 08:00产品发布/更新
服务端短暂保存对话，长代理循环的首字等待有望下降。
▾

深度解读

Anthropic 的 Messages API 推出消息线程测试功能。创建线程时提交完整消息、系统提示和工具配置，此后请求只需发送新消息以及上一条响应的标识，由服务端重建对话。官方文档称，这能减少长会话反复上传、验证和分词的工作；报道提及在五十万至一百万词元请求中，首词元时间中位数下降约百分之三十五。线程是尽力保存的临时状态，并非永久对话数据库。

开发者仍需自行保存完整消息，线程在最近一次请求五分钟后过期，无法继续时应重新发送完整历史；每个响应标识只能续接一次，分叉或修改旧轮次要创建新线程。文档还说明内容在内存中加密保存，最后使用后不超过一小时删除，但该功能不符合零数据保留或 HIPAA 条件。更短的请求不等于模型处理的上下文消失，也不改变既有价格和速率限制，因此接入决策要同时考虑延迟、恢复逻辑与数据政策。

来源：Anthropic 开发文档

OpenAI 用 Pando 重建 Git 后端

OpenAI11月02日 23:30产品发布/更新
兼容 Git 客户端，支撑 Codex 带来的并发开发。
▾

深度解读

OpenAI 披露内部 Git 后端 Pando 的设计，称 Codex 让工程师与代理同时创建更多分支、提交和持续集成任务，原有单体仓库系统一度难以支撑，可靠性有时低于百分之九十。Pando 沿用 Git 协议和客户端，对不同分支分别协调写入，并重复利用压缩后的对象包为多个读取请求服务。公司称上线后推送延迟中位数接近缩短五倍，每日传输近一拍字节 Git 数据。

按分支并行写入避免无关分支互相等待，但跨多个分支读取时，客户端可能看到不同时间点的状态；复用数据包节省服务器重复打包，也可能让客户端多下载一些已有对象。这个权衡针对的是代理高并发修改同一大仓库的场景，并非所有小型项目都需要新建类似系统。OpenAI 表示希望将客户端改进回馈 Git 项目；内部数据说明了其自身负载下的效果，不能直接外推为其他团队一定获得同样倍数的收益。对于需要频繁克隆仓库的持续集成系统，缓存命中率也会影响实际网络开销。

来源：OpenAI

The Verge 报道，Anthropic 更新 Claude Code 的系统提示，对复刻现有游戏提出限制。这一变化发生在编程代理能够根据自然语言快速生成交互作品的背景下，也引发开发者对经典游戏机制、受保护的角色和素材之间界限的讨论。相关规则是 Anthropic 产品的行为设定，具体请求会否被拒绝取决于提示内容及服务实际执行情况，不等同于法院对某个作品的版权裁决。

▾

深度解读

Sierra 介绍围绕 Ghostwriter 重新设计 Agent Studio：运营人员可以在同一个会话里排查解决率下降，查看实际对话，修改智能体的 journey，再测试拟议修复。这里的 journey 是智能体完成业务流程所遵循的步骤；报道描述的是把分析和编辑连接起来的工作界面，而不是宣布所有客户问题均能由模型自主解决。公司希望减少在分析面板、配置页面和测试环境之间反复切换的成本。

如果某类退款咨询解决率下降，团队需要先识别失败对话是否集中在身份核验、政策解释或系统调用，再针对出错环节调整流程。把历史会话和测试放在编辑界面附近，可以缩短提出假设到验证的路径；但自动给出的原因仍需与原始对话核对，避免把用户转人工误判为成功。生产部署还涉及权限、敏感对话和回滚机制，界面整合本身不能证明新流程在所有客户群上均有更高解决率。Sierra 表示修改先保存在会话中，经过团队审查和合并后才会进入发布流程。

▾

深度解读

OpenAI 推出 Grid Protectors 计划，表示将与电力公司和监管机构合作，让未来计算园区在电网紧张时降低用电。首个试点是仍在开发中的佐治亚州 Effingham County 园区；公司称与 Georgia Power 的协议包含最多一千兆瓦的灵活需求响应，相当于约七十万户家庭的平均用电需求。该数字是计划中的最大可调负荷，不代表园区已经在某次极端天气中实际释放了这一电量。

Addy Osmani：给智能体循环设目标与停止条件

深度解读

Addy Osmani 在 O’Reilly 转载文章中讨论实践中的循环工程：让代理围绕明确目标反复行动、测试结果并调整，而不是只生成一次答案。作者表示自己通常同时使用五至十个代理；对边界明确、停止条件清楚的任务，他愿意更多放手，对另一些任务则保留更密切的代码审查。文章强调，人应继续负责判断目标和约束是否正确，循环只是执行与反馈机制。

以修复测试失败为例，可以先写明允许修改的目录、必须保持的接口、要运行的测试和达到条件后的停止规则。若测试只覆盖错误路径，代理可能通过删除断言或改变需求让测试转绿，因此审查还要检查补丁是否解决原问题。多个代理并发也可能修改同一文件或制造互相冲突的假设，适合把任务拆成清晰边界，并在整合后运行整体验证；循环次数增加本身并不是质量指标。文章转载的是作者此前的实践经验，并非一次受控实验对所有开发流程的统计结论。
