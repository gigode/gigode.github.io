GPT-Live-1.1 开放 API，实时语音支持自然打断

OpenAI / Vercel11月20日 04:00模型发布/更新
OpenAI 的 GPT-Live-1.1 已向开发者开放，Vercel 同日宣布在 AI Gateway 提供该模型。
▾

事实与分析

OpenAI 的 GPT-Live-1.1 已向开发者开放，Vercel 同日宣布在 AI Gateway 提供该模型。它是全双工语音模型，可以在输出语音时继续听取输入，允许通话者中途暂停、打断或补充信息。Vercel 称，相比上一代 GPT-Live，新版本的转写更准确，跨语言对话中的口音与声音也更一致。现有集成沿用 Live 端点及客户端委派机制，切换时使用新的模型标识即可。开发者仍应以自己的语言、音频质量和使用场景测试识别表现，公开介绍中的对比不等于所有场景都达到同一提升幅度。原文还展示了将复杂任务委派给文本模型，并把结果交回语音模型继续播报的接入示例。这一更新使已有 Live 集成可以沿用接口；示例也说明语音交互与后端文本推理可以分别处理。

Zoom Scribe V2.1 Pro Live 获流式转录评测第一

AGI Hunt / Artificial Analysis11月20日 07:40模型发布/更新
独立评测机构 Artificial Analysis 对 Zoom Scribe V2.1 Pro Live 进行了流式语音转文字测试。
▾

事实与分析

独立评测机构 Artificial Analysis 对 Zoom Scribe V2.1 Pro Live 进行了流式语音转文字测试。AGI Hunt 转述其结果称，在 AA-WER Streaming 的最终转录准确率项目中，该模型词错误率为 2.4%，略低于 MAI-Transcribe-2-Streaming 的 2.5%；该榜单覆盖四十多个模型。词错误率越低，代表在这项测试中识别错误越少。准确率之外还需要考虑响应速度：报道显示，Zoom 在语音结束后返回最终转录的时间为 0.66 秒，微软模型为 0.13 秒；首次部分转录的错误率和延迟也分别为 5.0% 和 0.55 秒，对照模型为 2.5% 和 0.12 秒。这些结果反映的是所用测试集和评测口径下的比较，不能直接推断所有语言、噪声环境或应用场景的表现。对实时字幕与会议记录等用途，使用者可以同时比较最终文本质量、部分结果质量和延迟，并用自己的录音验证。

来源：AGI Hunt / Artificial Analysis：https://agihunt.info/en/p/1a1f632f9d03d2034c3f4b042b8

Gemini API 预览 Tool Retrieval，按需加载工具参数

Google11月20日 02:00产品发布/更新
Google 在 Gemini Interactions API 中预览 Tool Retrieval，针对智能体接入大量工具时，每次请求都携带完整参数定义带来的输入词元和延迟开销。
▾

事实与分析

Google 在 Gemini Interactions API 中预览 Tool Retrieval，针对智能体接入大量工具时，每次请求都携带完整参数定义带来的输入词元和延迟开销。开发者可在请求中加入 tool_search，并为需要延迟加载的工具设置 defer_loading；模型仍可看到工具名称及描述，当需要使用某项工具时，API 再加载其完整参数定义，同一请求内完成检索和函数调用。调用步骤可在返回结果中检查，方便调试工具名称与描述。官方表示，不需要开发者自行建立或托管索引，常用工具仍可提前加载；该机制也支持远程 MCP 服务器，以及由应用自行执行检索的客户端模式。当前功能处于预览阶段，实际节省量取决于工具库与使用场景。

来源：Google：https://blog.google/innovation-and-ai/technology/developers-tools/gemini-api-tool-retrieval/

Together 推出 GPU 集群免费数据缓存层

Together AI11月19日 08:00产品发布/更新
Together AI 推出 Storage Accelerator，作为 Together GPU Clusters 自带的分布式缓存层，目标是减少训练或推理任务从对象存储和 Hugging Face Hub 重复拉取数据的开销。
▾

事实与分析

Together AI 推出 Storage Accelerator，作为 Together GPU Clusters 自带的分布式缓存层，目标是减少训练或推理任务从对象存储和 Hugging Face Hub 重复拉取数据的开销。公司介绍，缓存运行在集群 GPU 节点上，首次读取的对象写入集群 NVMe，后续其他节点读取时可从集群内部获取；现有应用可通过配置端点使用，无需更换 SDK 或重写数据加载器。官方在一台 H100 节点上的测试显示，一个 2 GiB 对象从跨云来源直接读取耗时约 13 至 15 秒，命中缓存后约 0.6 至 0.7 秒。该测试只是特定条件下的结果，官方亦提醒速度取决于源站、对象大小和网络路径。该功能随 Together GPU 集群免费提供。

来源：Together AI：https://www.together.ai/blog/introducing-together-storage-accelerator

Google 介绍跨数据中心训练中的 Streaming DiLoCo

Google Developers Blog11月19日 00:00技巧与观点
Google 开发者博客介绍在开源 JAX 大模型训练框架 MaxText 中实现 Streaming DiLoCo，目标是应对跨数据中心训练时广域网带宽较低、延迟较高造成的同步等待。
▾

事实与分析

Google 开发者博客介绍在开源 JAX 大模型训练框架 MaxText 中实现 Streaming DiLoCo，目标是应对跨数据中心训练时广域网带宽较低、延迟较高造成的同步等待。DiLoCo 把训练分成多个学习组，各组先在本地数据上独立进行若干优化步骤，再跨组平均权重变化并执行外层优化。这样可以减少跨组通信频率，但如果在同一时刻一次传输整个模型的权重变化，仍可能出现周期性停顿。Streaming DiLoCo 将参数拆成若干片段，在一个同步周期的不同步骤逐片传输，避免把通信集中在单一步骤。文章也提醒，组内设备仍按原有方式通信；所述方法针对跨组通信问题，其适用效果取决于具体网络条件和训练配置。

来源：Google Developers Blog：https://developers.googleblog.com/distributed-llm-training-across-metros-streaming-diloco-in-maxtext/
