公众号：小红书技术（dots.llm）09-14 17:59模型发布/更新
小红书 AllSpark 团队开源 Search Agent 专用模型 Iris，权重与评测代码同步公开。
▾

深度解读

小红书 AllSpark 团队发布了 Search Agent 专用模型 Iris 并直接开源，权重和评测代码已一并公开，训练数据与配方将陆续释出。值得注意的一点是它同时给出了 35B 与 397B 两个尺寸，官方称两者在同量级对比中成绩领先——这意味着团队并不只是追求大参数堆叠，而是刻意验证在搜索这类高工具调用密度场景下，中小尺寸模型能否通过架构与训练配方优化追上大模型。搜索智能体是当前 agent 落地中最烧 token、对多轮工具调用稳定性要求最高的品类之一，此前开源社区缺少专门针对该场景做过系统性后训练的基座。

从产业角度看，这条消息的信号意义大于单点性能：小红书并非传统意义上的模型公司，其 AllSpark 团队把资源投向 Search Agent 而非通用对话模型，说明内容平台正把模型能力直接对准自身的检索与推荐场景。开源权重则是争夺开发者心智的常规打法——先用口碑建立技术品牌，再反哺自研业务的人才与生态。对国内开发者而言，这提供了一个可自部署、可微调的搜索智能体基座选项，绕开了对闭源 API 的成本与合规依赖。后续需要观察的是训练配方的公开程度，以及 35B 版本在真实长尾检索任务上的泛化表现，这两点决定它能否被真正用起来。

DeepSeek V4.1-Flash 技术细节公开：1M 上下文、FP4 KV 缓存、跨层注意力复用

MarkTechPost09-10 15:31模型发布/更新
V4.1-Flash 为 552B 主干 MoE，全局 KV 缓存降至每 token 890 字节。
▾

深度解读

MarkTechPost 披露了 DeepSeek-V4.1-Flash 的完整技术规格：这是一个多模态 MoE 模型，主干 552B 参数另加 196B Engram 参数，上下文窗口拉到 1M token，prefill 阶段激活 8B、decode 阶段激活 16B。最核心的工程突破在显存占用——全局 KV 缓存被压到每 token 890 字节，约为 DeepSeek-V4-Flash 的四分之一、DeepSeek-V1 的四百三十七分之一。这是靠 FP4 量化 KV 缓存与跨层注意力复用两项技术叠加实现的，同时模型采用全新的 Causal Encoder-Decoder 架构并具备原生视觉理解能力。

这组数字的意义需要放在 Agent 场景里读。长任务智能体的瓶颈早已不是单次推理算力，而是随对话轮次线性膨胀的 KV 缓存把显存吃干，导致要么限制上下文、要么付出极高的 HBM 成本。把每 token 缓存压到 890 字节，等于在同等硬件上把可服务的并发会话数或上下文长度提升数倍，直接转化为单位 token 成本下降——这也是 DeepSeek 敢于同步下调 API 价格的技术底气。跨层注意力复用如果确实稳定，还可能被其他厂商跟进成为新一代长上下文模型的标准做法。需要留意的是 FP4 量化对超长上下文召回精度的影响，公开评测里尚未见到 1M 长度下的针尖测试数据。
