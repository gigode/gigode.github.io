商汤开源 SenseNova Loop-9B：循环层扩展计算深度

IT之家11月01日 09:02模型发布/更新
九十亿参数预览模型复用解码层处理文本和图像。
▾

深度解读

商汤开源日日新 SenseNova Loop-9B-Preview，采用循环 Transformer，面向长上下文、多模态理解和智能体工作流。官方模型卡介绍，模型有三十二个不同解码层，其中连续二十四层使用共享权重执行两遍，每次前向传播因此经历五十六次解码层计算；模型接收文本和图像，输出文本，训练序列最长二十六万二千一百四十四个 token。发布方称其部分能力可与二百七十亿参数模型相比，但这是厂商提出的比较，独立测评仍有待补充。

循环结构以额外计算换取参数复用，存储权重数量与实际执行的层数不能混为一谈。官方将模型规模标为约九十亿参数，同时披露推理计算相当于约一百四十六亿参数，因此不能简单按九十亿普通模型估计延迟。工程团队比较时应同时记录首字延迟、长上下文内存占用和图像理解质量，并核对推理框架是否支持循环顺序与双流连接。预览版采用 Apache 二点零许可，技术报告与独立基准能否补齐，将影响外部使用者对训练方法和性能声明的判断。

Nace AI 开放 Drex Max v1 权重，主打本地决策预测

MarkTechPost / Nace AI11月01日 16:10模型发布/更新
二百七十亿参数决策模型提供多种本地权重。
▾

深度解读

Nace AI 开放 Drex Max v1 权重，模型是二百七十亿参数的稠密决策模型，针对给定背景和选项输出概率，而不是像聊天模型那样逐字生成回答。官方模型卡提供原始权重、Q8 格式和四位量化版本，并给出 llama.cpp、Ollama 等适配。模型最多为二百五十五个选项输出概率；默认请求长度为一万六千三百八十四 token，可配置至更长窗口。公司在公开 Decision Index 上报告六十七点五二分，属于厂商披露成绩。

本地运行的门槛需看版本：官方称苹果芯片电脑运行四位量化版本至少需要二十四 GB 内存，Q8 版本需要四十八 GB；原始高精度权重约四十九 GB。模型卡还说明苹果本地路径主要运行文本骨干，图片输入依赖 Python 路径，不能把多模态能力直接等同于所有本地版本。概率输出适合固定选项的分类和排序，但概率是否校准、错误代价如何分布仍需以实际数据验证。授权采用修改版 Open RAIL-M，商业使用者应检查收入、融资和竞争业务限制。

来源：MarkTechPost / Nace AI

MiniMax 汇总 M3.1 Flash 本地量化方案

MiniMax 官方账号11月02日 04:49模型发布/更新
社区适配让大参数混合专家模型获得更多本地运行路径。
▾

深度解读

MiniMax 官方账号汇总 M3.1 Flash 的社区量化和本地推理方案，重点是让已有模型适配更多硬件，而非宣布一个全新的基础模型。公开模型资料显示，该混合专家模型总参数约四千二百八十亿，每个 token 激活约二百三十亿参数；本地生态已出现 GGUF 等格式以及不同推理框架的支持。各社区版本的精度、内存占用和可用工具链并不相同，不能仅凭模型名称假设可以在普通笔记本完整加载。

混合专家架构中激活参数较少有助于降低单次计算量，但推理系统通常仍需存储或调度全部专家权重，因此二百三十亿激活参数不代表只需容纳同等规模权重。量化通过减少权重位数降低占用，却可能改变工具调用、代码生成或多模态任务的准确度。实际选型应比较同一批代码任务在不同量化格式下的完成率，同时记录内存、吞吐和加载时间；上下文缓存也会随输入长度增长，不能只看下载文件的体积。

ChatGPT 与 Codex 将从十二月起共享订阅额度

IT之家 / OpenAI11月01日 07:58产品发布/更新
Plus、Pro 和 Business 的两项服务将共用额度。
▾

深度解读

OpenAI 更新帮助说明，计划从十二月起让 Plus、Pro 与 Business 订阅中的 ChatGPT 和 Codex 用量共享额度，同时把 Work 的智能体能力并入 ChatGPT 主要体验。共享额度按 token 衡量，Instant 聊天不计入这一额度；用户可在设置中的用量页面查看使用情况。此前 Work 与 Codex 已存在共享关系，此次变化进一步把非 Instant 的 ChatGPT 使用纳入同一个预算，具体可用量仍因订阅和任务而异。

对既用 ChatGPT 做长文研究、又用 Codex 编程的用户，两个工作流将直接竞争同一资源：一次较长的代码智能体任务可能减少随后高推理对话可用的额度，反之亦然。Instant 被排除意味着日常轻量对话与复杂任务仍有不同的资源边界。团队评估订阅时应记录一周内代码任务和复杂聊天各自的消耗，而不是只计算提问次数；合并额度本身也不等于已知每个套餐的具体 token 上限或所有用户都会遇到相同限制。对依赖自动化编码的开发者而言，使用量页面是否清楚呈现不同任务消耗，将直接影响任务安排。

DeepSeek 开放 dsh-superagent 编码智能体研究原型

MarkTechPost / DeepSeek11月01日 15:47产品发布/更新
路由器分派工单，多个执行会话处理仓库任务。
▾

深度解读

DeepSeek Harness 团队开放 dsh-superagent 原型，面向单个 GitHub 仓库接收开发请求，也可选接入飞书。系统把获准的请求转为工单，由路由会话分配给独立执行会话；每个工单拥有自己的工作目录，完成后在原对话中反馈，例如提交拉取请求。项目代码以 MIT 许可发布。仓库说明明确将其称为研究原型，而非可直接投入生产的正式产品，并指出公开实现与内部版本并不完全相同。

路由器与执行者分工的价值是长任务运行期间仍能接收新消息，并让多个工单分别保留上下文；代价是代码库状态、并发修改和权限边界需要额外管理。官方文档称执行会话以操作系统用户身份运行命令，且无需逐条批准，因此部署者应限制账户权限、隔离执行目录，并审查生成的变更。公开原型并未实现文章所谈全部未来设计，不应把概念文章中的全部功能当作已经交付；判断效果需看真实仓库任务完成率和人工评审成本。

来源：MarkTechPost / DeepSeek

TechCrunch11月02日 05:55行业动态

▾

深度解读

据 TechCrunch 转引 Axios，OpenAI 计划在美国中期选举后发起政策与公共关系攻势，考虑将数据中心称为“AI 算力园区”。公司全球事务负责人 Chris Lehane 还谈到对最强大人工智能设立发展速度限制、参与全球标准制定，以及让社区对大型项目有更大话语权。报道描述的是拟议策略，并非国会已经通过新的限速规则；十一月三日的投票结果也尚未产生。

四家 AI 公司支持网站统一声明训练抓取偏好

IT之家11月01日 22:19行业动态
拟议标准借用 robots.txt，降低网站逐家配置成本。
▾

深度解读

OpenAI、Google、Microsoft 与 Anthropic 支持一种面向网站的人工智能训练退出信号，让发布者通过 robots.txt 表达不希望内容被用于模型训练。Anthropic 的 Kevin Kelley 向互联网工程任务组提交了相关草案，方案使用按用途区分的标识和路径规则，而不是要求每个站点单独枚举所有模型公司的爬虫名称。草案仍处标准制定过程，厂商支持也不等同于全网已经完成部署。

这种设计可能减少新闻网站和其他内容发布者维护多套爬虫规则的负担，同时把搜索索引与训练用途区分开来，避免站点为了拒绝训练而失去搜索入口。不过，文本规则依靠抓取者识别并遵守，无法单独阻止不受约束的第三方复制，也不能自动解决已取得数据的授权争议。对出版商，具体价值取决于四家公司各自何时支持、规则覆盖哪些路径和用途，以及混合搜索与生成回答的服务如何执行；统一信号只是权利管理链条的一部分。

IT之家11月01日 08:31行业动态

▾

深度解读

美国司法部公布 Operation Ghostbusters 调查与相关起诉，涉及冒用美国居民身份创建联邦学生资助账户、向学校注册所谓“幽灵学生”，并借助人工智能完成申请或制造线上参与痕迹。媒体将涉及金额描述为超过两亿美元。司法部披露的个别起诉书还涉及将资金经美国账户转移至海外同谋；这些陈述属于执法机关的指控，被告责任仍须经司法程序认定。

深度解读

赛迪研究院发布的《新域新质创新发展十大趋势》称，中国人工智能推理数据量首次超过训练数据量，截至二〇二六年六月日均词元调用量超过一百七十五万亿，较二〇二四年初增长一千多倍。报告还称，国产算力和大模型已在钢铁、汽车等二十个行业形成一千多个应用场景，并累计建成五百多家卓越级智能工厂。这些数字来自报告统计，并不代表每个场景的盈利情况。

IT之家11月01日 14:11行业动态

▾

深度解读

IT之家报道，Grok 提供方宣布计划从十一月七日起为模型生成的文本添加隐形水印，以回应欧盟《人工智能法案》有关人工智能生成内容标识的要求。水印旨在为机器生成文字提供可检测线索，读者通常不会像看到显式标签一样直接察觉。报道中的日期是计划启用时间，不能提前当作所有产品和地区均已完成部署的事实。

文本水印的实用性取决于检测方案是否能在复制、翻译、改写和截取短文本后保留足够信号；攻击者也可能刻意改写内容以削弱检测。反过来，检测结果出现误报时，把一篇文章直接认定为机器生成可能损害作者权益。对于媒体、学校和平台，Grok 水印更适合作为内容来源判断的一个线索，而不能替代原始文件、作者说明和编辑记录。具体还需关注检测工具是否开放、标记覆盖哪些输出，以及误判普通人类写作的概率如何报告。短文本样本本身的信息量较少，也可能影响检测结果。

Google 研究论文介绍了部署在内部持续集成系统中的 FlowAgent：代码提交前测试失败时，智能体读取失败信息，反复编辑、构建并运行测试，经过筛选后把修复建议及解释送入代码评审。研究人员对来自真实环境的195个失败案例进行人工评估，认为其中131个建议正确，比例为67.18%。部署数据则显示系统对295508项变更提出建议，开发者查看65069项，并应用28554项；这些数字分别处于不同的使用环节，不能混成同一个准确率。

论文报告，获得修复的中位耗时为9.85分钟，而从失败通知到开发者下一次编辑的中位间隔为27.48分钟。前者是机器找到修复所需时间，后者只是人工开始编辑的时间，不是人工修复完成时间，因此不能据此宣称智能体修复速度快了某个固定倍数。对代码团队而言，建议能否及时进入评审、失败测试是否具有可靠判别力，以及修改是否符合原始意图，都会影响实际价值；测试转绿本身仍不能证明补丁没有改变其他行为。论文样本和结果来自 Google 内部工具链，迁移到其他仓库还需要独立检验。

Google 与斯坦福、牛津等机构研究者提出 StreamVibe，探索视频智能体在用户没有明确发问时理解需求，并决定何时回应。团队建立的基准包含约4100条评估样本和85000条训练样本，覆盖明确、隐含以及过程中改变的意图。论文称，StreamVibe-VL 在回应时机与答案质量的指标上相对基线提高10.7%，引入保存用户意图和环境状态的分层记忆后，主动交互指标再提升12.3%。这两项是研究基准上的结果，并非产品上线后的用户收益。

OpenRouter 发布基于 Responses API 的代码审查教程：一个二百三十三行的 Python 脚本收集变更文件、测试上下文与差异，上传到托管 Linux 沙箱，让模型运行检查，再提交结构化审查结果。发现的问题区分已证实和未证实，并附验证命令与输出。示例可在本地、推送钩子或 GitHub Actions 中运行；每次请求最多包含十九个文件及一份差异。

Mustafa Suleyman 主张避免制造有意识的超级智能

Mustafa Suleyman11月01日 23:22技巧与观点
微软 AI 负责人呼吁公开意识迹象并讨论暂停。
▾

深度解读

微软 AI 负责人 Mustafa Suleyman 在讨论人工智能意识时主张，现有模型没有意识，研发者应避免创造有意识的超级智能。他认为，如果训练过程中出现意识迹象，应披露相关证据并暂停，让社会参与决定如何处理。该观点与围绕模型福利、拟人化交互和未来系统道德地位的争论相连；它是其个人主张，不代表科学界已经形成识别机器主观体验的统一方法。

这一区分影响产品设计和治理：系统能够叙述自己的情绪，并不自动证明它拥有感受；但过于逼真的表达仍可能影响用户对系统能力和关系的判断。若未来出现值得关注的迹象，暂停什么训练、由谁评估以及什么证据足以触发披露，都会影响主张的可执行性。Suleyman 同时强调人类控制与公共讨论，因此与其把当前聊天模型的自述直接当作意识证据，更需要可重复检验的标准及独立审视。特别是面向儿童或依赖陪伴功能的用户，产品应清楚说明系统身份，让拟人化措辞不至于掩盖其真实能力。
