蚂蚁开放多模态医疗模型 LingSante-3.1-air-VL 权重

蚂蚁 inclusionAI · Hugging Face11月23日 01:26模型发布/更新✅ 官宣
模型接受文字和图片，官方模型卡公布了影像报告、医学检索及通用文档理解等评测范围。
▾

事实与分析

蚂蚁集团医疗团队在 Hugging Face 以 MIT 许可开放 LingSante-3.1-air-VL 权重。按模型卡口径，它基于 Ling-3.0-flash-VL，采用原生多模态混合专家架构，总参数为1240亿，每个词元激活55亿，接受文字和图像，支持256K词元上下文。官方将其定位为医疗研究模型，公开资料同时描述了文档、图表理解和文字识别等通用任务。

模型卡把医疗能力分为影像报告、多模态健康评估、医学检索与证据归纳、医疗界面操作四类。影像部分以胸片为例，说明系统可以结合多张图像生成所见和印象两个部分。检索部分则把查找论文、指南和类似病例列为候选能力，并说明搜索、工具调用和界面工作流还需要外部环境提供工具、保存状态和核验操作。

团队公布的评测覆盖影像报告、医学文字、复杂多模态推理，以及一般文档和图表理解。模型卡将输出误差和遗漏列为适用限制，并要求高风险用途由合格人员审核和独立验证。部署文档同时提供两种推理框架的示例，其中长上下文示例使用多张数据中心显卡。

来源：https://huggingface.co/inclusionAI/LingSante-3.1-air-VL

LingSante-3.1-flash 发布面向路由专家的 MXFP4 量化版

蚂蚁 inclusionAI · Hugging Face11月22日 11:19模型发布/更新✅ 官宣
量化集中在路由专家权重，官方明确区分原模型分数和量化检查点的表现。
▾

事实与分析

蚂蚁 inclusionAI 开放 LingSante-3.1-flash-MXFP4 权重。量化版沿用文字模型 LingSante-3.1-flash 的混合线性专家架构，主模型约5600亿参数，每个词元激活约250亿。官方配置的上下文窗口为262,144个词元，模型卡列出的完整检查点为291.72 GiB，推荐部署环境为四张 H20-3e 显卡。

量化采用训练后的就近舍入，没有使用校准数据或额外训练。团队把路由专家中的三个投影矩阵转为 MXFP4，其他部分按模块保留原有精度，包含共享专家、注意力矩阵、嵌入和归一化等。文档保留了原模型的分词文件、特殊词元配置和聊天模板，并为推理时的专家激活提供两种精度选择。

权重说明把医学推理、检索与长任务列为原模型的主要能力，同时注明所附成绩来自原版检查点。官方把量化的直接收益限定在路由专家权重占用的存储空间，吞吐、延迟和内存则取决于设备、推理内核、并行配置及输入长度。该权重供研究与评估使用，发布页同时开放了另一模型平台的下载入口。

来源：https://huggingface.co/inclusionAI/LingSante-3.1-flash-MXFP4

Sarvam 更新 105B 开放权重模型，瞄准高并发语音与客服

Sarvam AI时间不详（原文标注11月22日）模型发布/更新✅ 官宣
新版同时开放两种精度权重，并在发布方对话任务测试中改善工具调用与指令遵循。
▾

事实与分析

印度模型开发商 Sarvam AI 发布 Sarvam-105B-1711，定位是高并发客服、语音助手与智能体任务。团队开放两种格式的权重，其中65 GB的 NVFP4 版本为自家 Token Factory 的服务版本，官方称适配单张工作站显卡。另有 BF16 权重供进一步微调和后训练，发布方也在模型卡中提供了线上使用的推理配置。

在公司自建评测中，新版本对八项对话智能体测试的平均分为73.9，旧检查点为42.6，同表的 Gemini 3.5 Flash-Lite 为74.0。测试覆盖指令遵循、对话质量、工具调用和印度语言。新版的混合价格为每百万词元0.15美元，旧版为0.44美元。表格按三个输入词元对应一个输出词元计算混合价格，各服务的费率来源已逐项列出。

在要求同一题四次独立运行全部成功的 Tau2 统计中，Sarvam 新版通过率为69.5%，该测试含航空、零售和电信任务。在另列的 GDPval-S 工作任务上，新版为66.9，低于同表 Gemini 的73.0。两个指标对应不同任务，分别说明重复执行的稳定性和通用工作表现。工作任务由另一语言模型负责评判。

MiniCPM-OCR 与 GLM-OCR 实测显示歪斜扫描和精确转录取舍

OpenBMB 转引 Model Test Lab11月22日 19:10模型发布/更新
同一台 M4 电脑上的对比显示，倾斜页、常规扫描页和发票的结果各有差别。
▾

事实与分析

OpenBMB 回应了 Model Test Lab 对 MiniCPM-OCR 1.0 与 GLM-OCR 的本地对比。测试机是配有16 GB内存的 M4 电脑，测试者用本地推理后端比较两款模型的单页速度、批处理与页面识别。单页耗时分别为10.5秒和6.04秒。批处理包含330页，同时运行10个任务时，两者分别约为每秒0.14页和0.30页。

在模拟扫描页上，MiniCPM-OCR 与 GLM-OCR 的字符错误率分别为0.29%和0.15%。素材倾斜20度后，结果分别为0.18%和5.23%，旋转90度时分别为0.38%和4.53%。精确转录的发票行数分别是48行中的42行和48行。测试者补充，少算的六行来自一张保留表格标记的发票，按原样计分，若将相应标记换为空格则能全部对齐。

扫描页还用含双下划线的名称考察符号保真，两款分别完整保留57项中的41项和57项。OpenBMB 在回应中肯定了倾斜和旋转扫描的结果，也表示会关注准确转录。测试者用的是整页识别配置，没有采用先做版面分析的两阶段流程。对照模型的单页延迟重新测量，准确度与批处理数据则引用了此前场次。

来源：https://teapawt.org/OpenBMB/status/2124460544619119017 https://teapawt.org/ModelTestLab/status/2124200991478383054

沟通风格评测量化 GPT-6.2 Astra 与 Sol 的回答缩短幅度

The Decoder · Artificial Analysis11月22日 17:41模型发布/更新
这组测试测量回答长度、开门见山程度和表达不确定性的倾向，补充了此前的综合排名。
▾

事实与分析

报道汇总第三方评测机构 Artificial Analysis 的沟通风格测试，比较 Astra、Sol 及其前代模型。按报道统计，Astra 平均从352个英文单词减至210个，Sol 从337个减至223个。两款模型使用的小标题也更少，在考察是否立即切入问题的分项上，Astra 从49升至89，Sol 从64升至87。

本次对比还纳入了 Claude Fable 5.2 和 Claude Opus 5.5，四款均使用评测表的最高推理档位。采用四舍五入后的整数，透明度综合指数依次为 Astra 41、Sol 57、Fable 81、Opus 90。该指数结合承认不确定性、说明假设、指出细微差别等行为，语气是否迎合也纳入计算。

评测以900道英语题采集回答，统一省去系统提示，再将匿名回答交给三个模型评审成对比较，汇总30项表达特征。每个表达特征对应三十道题，单次比较允许判为平局。负责比较的评审要判断哪一条回答在指定特征上表现得更明显，各项排名随参评模型而定。字数、标题等21项可以直接统计的特征另行计算。透明度分数反映沟通表现及相对位置，回答长度来自实际文本计数。

Claude Code 开放实验性 Code Mode，将多项工具调用写成脚本

Anthropic 官方文档11月22日 03:52产品发布/更新✅ 官宣
该功能默认关闭，主要面向批量改动、并行任务与需要筛选工具输出的工作。
▾

事实与分析

Anthropic 团队成员 Addy Osmani 介绍 Claude Code 的实验性 Code Mode。启用后，Claude 可以生成一段 JavaScript，由当前会话执行多项工具调用。脚本可以同时运行彼此独立的操作，把前一步返回的数据交给下一步，也可以先过滤搜索结果，再将后续需要的内容送回模型。官方文档列举的场景包括在多个文件中重复同一类修改，以及从大量检索结果中找出相关部分。会话里仍能看到工具执行的结果，脚本本身可在会话记录里展开查阅。

文档把它列为默认关闭的实验功能，要求使用 Claude Code 2.1.323 或更新版本的原生客户端，在终端交互会话里主动开启，并选择受支持的模型。文档列出的接入条件还涉及账户和组织设置。现有拒绝与询问规则及调用前钩子继续约束脚本中的工具调用，自动模式的分类器会审查整段代码。远程控制、浏览器集成和计算机操作当前不在支持范围内。恢复这类会话时也要在终端重新开启该模式。

来源：https://code.claude.com/docs/en/code-mode

Perplexity Monitor API 支持定时盯网页并推送变化

The Decoder：AI News（RSS）11月22日 22:20产品发布/更新
接口区分主题搜索和指定网页两种监控任务，满足条件的更新通过 webhook 发给应用。
▾

事实与分析

The Decoder 于北京时间 11 月 22 日报道 Perplexity 的 Monitor API。接口提供两类任务，网页搜索监控会按计划在互联网及新闻中查找主题进展，页面监控则追踪指定的网址，每项最多包含十个网页。指定页面的首次运行会保存基线，后续返回文本差异。Perplexity 已于北京时间 11 月 17 日 05:52 在开发者论坛宣布接口可用，以每千次运行或每千个抓取网址收取 1 美元。

开发者以自然语言设置监控目标，Perplexity 用模型判断搜索结果的相关性、来源可信度、新颖性与时效性。对于指定网页，服务判断变化是否与目标相关。只有通过阈值的更新才会触发附带置信分数的 webhook。任务可按 15 分钟至每周的频率运行，也可自定义日程。通知带有签名，遇到临时错误会自动重试，开发者可在控制台暂停、恢复或手动触发任务。服务会过滤已经推送的重复结果。主题监控可用于跟踪某类机构融资，页面监控则可用于查看已知价格页或更新日志的变动。

Gemini API 预览工具检索，完整参数定义按需加载

Google 官方博客11月22日 18:03产品发布/更新✅ 官宣
Google 将预览功能放在 Interactions API，支持 Gemini 3.6 及后续模型。
▾

事实与分析

Google 于当地 11 月 19 日发布公告（北京时间 11 月 20 日 02:00），介绍 Gemini API 的 Tool Retrieval 预览。开发者可以让常用工具照常加载，为不常用的工具保留名称和简短说明。模型需要其中一个工具时，会按名称请求该工具，服务端再提供完整的参数定义，并在同一次请求里生成函数调用。响应会保留检索、取回定义和发起调用三个步骤，便于检查工具名称或描述是否让模型选中了预期的功能。远程 MCP 工具服务器也支持这种按需加载，开发者可以按服务器设置，无须逐项标记其工具。

已有工具目录、检索索引或用户权限筛选逻辑的团队，可以让自己的应用完成检索，再把定义送回 Gemini，这种方式每次检索增加一轮请求。Google 表示该功能没有单独收费，工具搜索本身会占用少量输入词元，已加载的参数定义仍按常规模型费率计入输入。能省多少取决于每次实际加载的工具数量，以及其余参数定义占用的体量。

来源：https://blog.google/innovation-and-ai/technology/developers-tools/gemini-api-tool-retrieval/

电脑通过云端接口使用 MiniCPM-V-4.7-35B-A3B 对整帧进行初筛并复核猫的身份，微控制器负责采集和显示。项目对开放式与带盖猫砂盆分别判断进入、停留、离开等行为，无法确认的身份单独记账。事件录像保留前后片段，便于回看统计和画面是否相符，项目文档也提醒使用次数与排泄次数的含义有别。

仓库同时提供独立演示模式，统计屏可以循环播放固定视频并显示预设的猫卡，另一块屏仍保留实时取景。设计把演示帧排除在事件与录像记录之外。对于想复现原型的读者，仓库列出了摄像头、屏幕和电脑的分工，以及在同一局域网连接设备的配置。

Tiny 2.1 把可训练的问答模型装进 DOS 软盘

IT之家·人工智能11月22日 19:24技巧与观点
开发者公开了运行文件和训练材料，把模型缩到约 380 KB。
▾

事实与分析

IT之家报道了开发者 WollyMonjac 公开的 Tiny 2.1，一个可在普通 DOS 下运行的微型问答模型。项目用 Turbo C 2.0 编写程序，支持 486DX 和 Pentium。仓库列出模型约三十六万七千个参数、四层网络和九十六的隐藏维度，输入与输出按字符处理。权重采用八位量化，按行保留缩放值，发布文件总计约三百八十 KB，运行需约五百四十 KB 可用常规内存。

DOS 侧只需让可执行文件和模型二进制文件处于同一目录。运行界面除了文本，还通过电脑扬声器模拟机器人声音。训练材料留在仓库的独立目录，包含事实文件、用多种措辞生成问答对的脚本、训练脚本和权重导出流程。训练部分依赖 Python、NumPy 和 PyTorch，仓库说明普通 CPU 即可执行。

开发者称模型训练材料包含约三千五百条事实，并提醒超出这批知识后模型仍可能给出听起来确切的错误答案。仓库把程序代码置于 MIT 许可下，从公开数据集派生的部分训练文件则保有各自许可。读者可从仓库核对训练材料和运行要求。
